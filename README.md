## 登录与展示范围

当前包含 **17 个账号：14 位谈判负责人及 3 个管理员**。页面只需输入密码，即可识别账号。人员按完整姓名映射，不按姓氏判断；账号标识用于管理清单，页面不要求另行输入用户名。

| 账号类型 | 01 整体谈判进展 | 02 负责人进展、03 谈判议程、04 供应商返利清单 |
| --- | --- | --- |
| 采购总体管理员 | 总体、BOM、non-BOM 汇总 | 全部负责人及供应商 |
| non-BOM 模具管理员 | 全部 non-BOM 模具汇总 | 全部模具负责人及供应商 |
| non-BOM 工装、设备和物流管理员 | 授权专项合计及各专项汇总 | 全部工装、设备和物流负责人及供应商；不含模具 |
| 谈判负责人 | 所属专项整体汇总；BOM 人员看全部 BOM，non-BOM 人员看本人所属专项 | 仅本人负责的工作、计划和供应商 |

普通负责人的 01 数字下钻展示专项计算口径及品类汇总，不展开其他负责人的供应商明细。管理员下钻可查看本账号范围内的供应商。筛选选项、搜索、排序、分页、弹窗和导出遵守相同展示范围。03 的占比以本人或本管理员管理范围的已分配目标为分母，不暴露采购全盘金额。

**这是用户确认采用的前端展示分流，不是服务端强制的数据访问隔离。** GitHub Public 仓库和生成 HTML 仍包含全量业务数据，源码和文件可被读取。密码校验值只控制正常页面流程，不应将其描述为防止源码访问或防篡改的数据保密系统。规则见 [账号与展示范围](docs/ACCESS.md)。

明文密码清单只在仓库外的本地私密交付目录保存，不提交至此仓库。公开配置只包含账号映射、盐值和密码派生哈希。会话按标签页保存于 sessionStorage，有效期 12 小时，配置版本改变后需重新登录；不保存明文密码。浏览器拒绝存储时，当前标签页仍可登录使用。

## 页面与交互

| 模块 | 功能 |
| --- | --- |
| 01 整体谈判进展 | 金额与供应商两列，总目标、总进度四卡；按账号和分类计算 |
| 02 负责人进展 | 负责人总览、准时完成灯号，以及已开展/待开展谈判供应商清单 |
| 03 每日/每周进度 | 按目标完成时间归集供应商、负责人、计划目标和已记录成果；待排期单列 |
| 04 供应商返利清单 | 主表背景、谈判策略、目标与结果；搜索、排序、分页、导出及详情 |

供应商详情保留三地质量交付、索赔、新项目产品和企划量及来源。实际谈成返利、索赔扣款、签约及财务兑现分别处理；目标完成日是截止日期，不是预约日期。

顶部提供 **Browser / Mobile** 切换。Browser 保留既有 67% 页面缩放；Mobile 使用正常缩放、触控控件和可展开卡片。两种模式共用数据和展示范围，切换不重置筛选或弹窗。首次访问按屏宽选择；手动偏好可在本机保存；?mode=mobile 或 ?mode=browser 可指定模式。无远程字体、运行时 CDN、追踪或在线回写，可本地打开生成 HTML。

## 构建与维护

编辑 src/dashboard.template.html、src/dashboard.css、src/dashboard.js 和 src/auth.js，然后依次运行：

- python tools/build.py
- python tools/validate.py
- node --check src/dashboard.js
- node --check src/auth.js

data/snapshot.json 是规范化业务输入。仅刷新主表可使用 tools/refresh_main_sheet.py 并显式指定源文件、工作表和截止日。供应商成员、负责人或专项变化后必须核对账号映射；不能因更新快照而自动扩大权限或无意重置密码。

原始 Excel、完整原表抽取、明文密码、私密交付文件和本机路径不得提交。每次发布完成数据及构建校验、17 账号范围检查、电脑/手机验证和至少 5 个独立会话的并发测试；实际完成状态以发布记录为准，不能因存在测试计划就声称通过。
