本版本按用户于 2026-10-28 确认的方案，在 GitHub Pages 提供密码识别的个人/管理员工作台。账号是看板内部展示身份，不是 GitHub collaborator 或 GitHub 登录账号。

人员使用稳定账号 ID 和源表完整姓名，不得用姓氏匹配。若某人负责多个专项，汇总分别覆盖其所属专项，明细仍仅本人记录。

## 四个模块

1. 整体谈判进展：按汇总范围计算目标、谈判数量、结果与比例。个人账号不显示采购总盘或其他专项数字。点击数字查看专项计算口径及品类汇总，不展开其他人的供应商。个人明细不得冒充专项总额的完整支撑清单。
2. 负责人进展：个人账号仅本人，选择器固定为本人；管理员显示本管理范围负责人。
3. 每日/每周进度：排期、待排期、搜索、结果和导出采用明细范围。期间计划占比的分母为本人或该管理员全部管理范围的已分配目标，页面说明分母；不使用无权查看的全表总额。
4. 供应商返利清单：只显示明细范围内记录。详情、策略、质量索赔、新项目、姓名链接、搜索、排序、分页和 CSV 均使用相同范围。

备注或谈判历程如包含已知范围外的供应商/负责人引用，页面整段改为跨范围记录提示，避免只隐藏姓名却留下其他人的金额。不会改写源文本；当前供应商的结构化目标、结果和来源仍保留。总体管理员范围完整，可查看原文。页面文字链接与 CSV 的“下一步”使用同一处理规则；识别范围以源表名称及已登记的唯一供应商别名为准，不能将此规则视为对任意自由文本的自动保密保证。

退出、切换和会话失效时清空已渲染业务内容、弹窗、表格状态、搜索、分类与人员筛选，避免上一身份残留。正式导航保留四个业务模块，旧 #guide 入口回到整体进展。

## 密码与会话

- 输入单个分配密码识别账号，不要求注册 GitHub/Vercel 或成为 collaborator。
- data/access.json 仅保存账号 ID、名称、role、owner 映射、版本、盐值及派生哈希。
- 明文密码仅存本地私密交付目录，不放仓库、测试日志、截图或 caseOS。发布采用明确文件白名单，避免误传。
- 会话使用 sessionStorage，按标签页独立，12 小时过期，配置版本变化后重新登录。不在 localStorage 保存登录信息；该存储仍用于 Browser/Mobile 偏好。
- 同标签刷新可恢复有效会话；禁用存储时当前页面可登录，但刷新需重输。共享设备使用完应退出。
- 换密码、增删人员或变更专项时，同步公开配置和本地交付清单，保留未要求变更的密码。公开文档不得列可用密码。

## 明确边界

**这是前端展示分流，不是服务端权限隔离。** 全量 snapshot.json 和 HTML 内嵌数据仍公开；知道文件地址的人可以读取，源码也包含原始数据。密码派生哈希、隐藏元素、会话与范围过滤不能阻止读取源文件或修改本机脚本。哈希用于避免直接公开明文密码，不改变全量数据已经交给浏览器的事实。

用户已选择该简化 GitHub 方案。维护及验收结论不能把测试通过表述为“未经授权无法获得数据”；测试证明正常页面和导出流程的范围一致性。

## 验收要求

- 17 个账号逐一核对目标、供应商数、人员、计划、弹窗及导出范围。
- 验证三类管理员边界，以及个人专项汇总与本人明细分离。
- 验证 1440、1920、390px 及较窄移动屏的登录、四模块、触控、弹窗及局部滚动。
- 至少 5 个独立会话同时登录、筛选、切换及导出，检查互不干扰；同浏览器不同标签页另行验证。
- 验证快速重复操作、错误密码、会话失效、刷新、退出、离线和禁用存储后的可恢复性。
- 检查控制台异常、空值与零、CSV 公式注入防护，确认发布包无明文密码。
- 压力测试限本地；线上只做有限部署烟雾测试。发布记录如实列已通过、失败和未覆盖项。
