# 数据与维护

## 输入与追溯

`data/snapshot.json` 包含 metadata、records、actions、summary、issues。records 是供应商明细；actions 是单独管理的 PMO 行动；summary 是核对后的聚合；issues 记录差异与缺失。

记录保留供应商、品类、负责人、目标金额、目标日期、实际字段、谈判线索及工作表行号。metadata 保留快照日、来源文件名、来源 SHA-256、币种、金额单位和数据范围。发布包移除了本机绝对路径和重复的原始单元格字典，保留业务内容。

本仓库不包含原始工作簿、完整原表抽取、个人电脑配置或 caseOS 连接凭证。业务字段并未匿名化，仓库可见性决定谁可以读取这些数据；客户端筛选不构成访问控制。

## 更新步骤

1. 在获授权的工作环境只读读取新工作簿，核对来源、表头、行数、币种和日期语义。
2. 生成同结构规范化快照；保留缺失 null，不填造结果。刷新 summary 和 issues。
3. 核对 README、docs/METRICS.md 及 src/dashboard.js 中的快照特定说明，尤其是总体缺口、PMO 统计和数据覆盖提示。
4. 执行构建与校验，检查所有相关指标，保存证据。
5. 按授权范围提交和发布；新快照不自动意味着原件上传、caseOS 后台完成或图谱已回读。

更新版主表 J 列为实际完成日期，K/L 为实际返利金额和比例。金额与比例仍可能带有不合适的日期格式，提取时读取底层数值并核对格式，避免把金额误解析为日期。新增的模具、工装和物流分表只用于核对，不与采购5921清单重复相加。

## 后续扩展

建议增加稳定供应商 ID、BOM/non-BOM 明细、目标版本、原截止日、每次计划及实际谈判日、下次动作、协议金额/日期、财务确认与到账/抵扣凭证。只有这些字段齐备后，才能完整回答历史谈判数量、按时率和真正兑现。

未来若增加在线录入或多人协作，需要另外设计身份认证、访问权限、历史版本和审计。目前是离线只读看板。
