# 数据与维护

`data/snapshot.json` 包含 metadata、records、actions、summary、issues。原始工作簿保持只读，不进入仓库。

## 主表

唯一供应商汇总来源为“采购5921清单”第 2–158 行，分类取 B，名称 C，品类 D，负责人 H。E–S 是背景与谈判线索；F 为返利目标，I 为目标完成时间，T/U/V 为实际完成日、返利金额、达成率。新增数据布局不能沿用旧版 J/K 实际字段。

提取使用 ZIP/XML 稀疏读取，避免隐藏表被错误扩展到百万行或万列。数值读取底层缓存值，日期仅对指定日期栏转换，防止错误单元格格式将金额解析成日期。保留零与空白的区别。源表公式使用文件保存的缓存结果，源文件不重算、不改写。

## 关联

- **索赔**：温州“索赔明细_温州 1021”，广东“索赔明细_广东 1021”，丽水“索赔金额__丽水 1021”。保留原因、金额、已扣、待扣或确认/开票/核销状态。不同地区没有的字段为 null，不从状态推算金额。
- **月度质量交付**：广东、温州各月 QCDS 表，丽水“26年1-8月源数据 (2)_丽水 1021”。不同布局分别映射合格率、目标、供货达成率、PPM 与投诉字段；不将评分或次数当金额。
- **名称匹配**：规范化空格和全半角，优先全称。编码映射来自账期表和温州 QCDS 中的编码/全称。简称只有在包含清单、账期和完整 QCDS 名称的名录中唯一命中时关联，保留原名和“唯一简称匹配”标签。模糊相似或多义简称不自动关联。
- **新项目**：优先“2027年量产新项目定点清单 1021”M 列整理后全称，其次 J 列。保留产地、客户、项目、代码、企划量原文、产品、T0、SOP 和来源行。未分配项目不强行归属。
- **谈判历程**：实际结果来自主表 T–V。10/27 的后续进展与下一步为滚动更新表 M20、M24、M25 的注明来源摘要。鞍能、明曜已经回填实际结果，下一步改为补充策略、效果及未达标补救记录，另引“10月 | 微信消息”C4。同一金额只在结果中计一次，后续进展不重复汇总金额。

每条明细保留工作表/行号。metadata 保存源文件名、SHA-256、快照日期和单位，不保存电脑绝对路径。associationAudit 记录未关联数，包含清单外供应商及缺关联信息，不代表全部都是错误。
